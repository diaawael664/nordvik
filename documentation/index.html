Nordvik documentation

W 100%

A furniture and home decor store template. This guide covers installing it, rebranding it, editing every piece of content, connecting a real shop, and deploying.

3 home layouts

Classic, Editorial and Modern, built from shared sections you can reorder.

Complete shop

Category pages, filters, product pages, cart, checkout, wishlist and account.

One-file theming

Three color presets with dark mode, fonts and layout options in theme.config.ts.

Backend-ready

Every page reads one catalog module. Sync from Shopify, or plug in your own platform.

Everything a customer sees comes from files in /data and /content, so most changes never touch a component. The site builds to static HTML, so it can be hosted anywhere and needs no server.

Installation

You need Node.js 20.9 or newer. Unzip the template, open a terminal in its folder, then: 

npm install
npm run dev

Open http://localhost:3000. Changes to any file reload the page instantly.

Command What it does
npm run dev Development server with hot reload.
npm run build Builds the static site into /out. This is the folder you deploy.
npm start Serves /out locally to check the production build.
npm run lint · npm run format · npm run typecheck ESLint, Prettier and TypeScript checks.
npm run test:e2e End-to-end tests against the built site (see Testing).
npm run placeholders Generates neutral placeholder images (see Images).
npm run catalog:shopify Syncs products from Shopify (see Connect a backend).

Store information

Open data/site.ts. Every setting has a comment. The most important ones:

Setting Use
name, tagline, description Shown in the header, footer, browser tabs and search results.
url Your live address, no trailing slash. Used for the sitemap, canonical links and share previews. Set it before you deploy.
currency, locale Formats every price, e.g. "EUR" and "de-DE".
contact, social Footer, contact page and Coming Soon page.
announcements Rotating messages in the top bar. An empty list hides the bar.
features The four promises in the features bar (icon names come from Lucide).
freeShippingThreshold, shippingFee, taxRate Cart and checkout totals.
demo.styleSwitcher The "Customize" panel. Set to false before going live.

Colors, fonts & logo

Color presets

theme.config.ts holds three complete presets, each with a light and a dark palette:

Oak & Pine

Warm linen, walnut and a fjord-pine accent. 2px corners.

Clay & Linen

Plaster neutrals and a fired-clay accent. Soft 10px corners.

Nordic Stone

Cool stone grays and a fjord-blue accent. Square corners.

Choose one with a single line:

export const activePreset: PresetName = "clay";

To use your brand colors, edit a preset's values. Each token has a job, documented in the file: bg (page), surface (cards, inputs), sand (tinted blocks), ink (text), muted (secondary text), line (borders), accent (buttons, links, focus), onAccent, wood (sale badges, ratings), inverse / onInverse (footer, announcement bar).

Every preset passes WCAG AA contrast (4.5:1) for the text and background pairs the template uses. If you change colors, check ink and muted on bg, surface and sand, and onAccent on accent, with a tool such as WebAIM's contrast checker.

Fonts

Fonts are loaded with next/font, which downloads them at build time and serves them from your own domain. Replace any import at the top of theme.config.ts with another Google Font and keep the variable name: 

import { Cormorant_Garamond } from "next/font/google";

export const fontDisplay = Cormorant_Garamond({
  subsets: ["latin"],
  weight: ["400", "500"],
  variable: "--font-display-face",
  display: "swap",
});

Logo and icons

  • Header and footer: by default the store name is set as a wordmark. For an image logo, put the file in /public and set logo: "/logo.svg" in data/site.ts.
  • Browser icon: replace public/icon.svg, public/favicon-48.png, public/apple-icon.png (180×180) and public/icon-512.png.
  • Share image: replace public/og.png (1200×630). Product and blog pages use their own photo automatically.

Layout options

The layout block in theme.config.ts switches layouts across the whole site:

Option Values
header "overlay": transparent over the Classic home hero, solid once you scroll. "solid": always solid.
shopFilters "left" or "right" sidebar, or "top": a filter panel that opens above a four-column grid.
productGallery "side" thumbnails, "bottom" thumbnails, or "stacked": every image large in a column on desktop.

The demo's "Customize" panel previews these options in the visitor's browser only. Your configured values are always what search engines and first-time visitors get.

Images

Components never contain image addresses. Every photo is a key in data/images.ts:

"sofa-velvet-green": {
  src: "https://images.unsplash.com/photo-…",
  alt: "Deep green velvet three-seat sofa on a pale oak floor",
},
  • Use your own photos: put them in /public/images/ and set src: "/images/my-sofa.jpg", or use any full URL. Always write an alt that describes the photo; screen readers announce it.
  • Product images are keys (or URLs) in each product's images list: the first is the card image, the second appears on hover.
  • Placeholder mode: run npm run placeholders, then set imageMode: "placeholder" in data/site.ts. Every photo becomes a neutral panel labelled with its key and description, so you can see what to replace. The template ships this way.
  • Switching modes at build time: the NEXT_PUBLIC_IMAGE_MODE environment variable (placeholder or unsplash) overrides imageMode without editing the file.

The live demo's photos come from Unsplash and are not included in the download. See Credits. Product and room photos have the biggest effect on how the store looks and on its loading speed: export them as WebP or AVIF, about 2000px wide, and host them on your own domain or CDN.

Remote images are resized through the custom loader in src/lib/image-loader.ts (Unsplash and Shopify CDNs are supported). Files in /public are served as-is, so size them before uploading.

Products & categories

Add a product by copying any entry in data/products.ts. TypeScript flags missing or misspelled fields as you type.

Field Notes
slug Its address: /product/<slug>/. Lowercase, hyphens.
category Must match a slug in data/categories.ts.
price, compareAt Setting compareAt (the original price) marks the product as on sale.
colors { name, hex, family }. family groups colors in the shop filter (families are in data/filters.ts). Add image to switch the gallery to that colorway.
options Extra selectors such as Size, with an optional priceDelta per value.
dimensions Centimeters. Drawn on the product photo and converted to inches on the page. Set width to 0 to hide dimensions.
stock 0 shows "Sold out" and a back-in-stock form. 1–5 shows "Only N left".
leadTime Plain text such as "Ships in 2–3 weeks". Also drives the delivery-date estimate.
isNew, isBestseller Badges, and the New arrivals and Best sellers lists.
materials Material filter. Fabric materials (velvet, linen…) show the free-swatch option.

Each category gets its own page at /shop/<slug>/. Reviews for the demo come from data/reviews.ts; add product-specific ones under byProduct, or replace the file with your reviews platform.

Home pages & sections

The three home layouts are src/app/(site)/page.tsx (Classic), home-editorial/page.tsx and home-modern/page.tsx. Each is a list of sections, so you can reorder or delete lines, or move sections between layouts: 

<HeroSlider slides={heroSlides} />
<FeaturesBar />
<CategoryTiles slugs={["sofas", "chairs", "tables", "lighting"]} />
<ProductRail eyebrow="Most loved" title="Best sellers" items={bestSellers()} />
<DealSection />
<Testimonials />
<Newsletter />

Available sections: HeroSlider, FeaturesBar, CategoryTiles, ProductRail, ProductGrid, PromoPair, StorySplit, DealSection, Testimonials, PressStrip, SocialGallery, Newsletter, VideoBand, CollectionShowcase and ShopTheRoom. Their text lives in data/home.ts.

To make Editorial or Modern your main home page, copy its file over src/app/(site)/page.tsx (and remove the original routes and their menu links if you don't need them).

The deal countdown uses deal.endsAt. For a real deadline, set repeatEveryDays: 0; otherwise the demo restarts the timer so it never shows as expired. The Home 3 video uses modern.video.src; leave it empty to show the still image only.

Menus

data/navigation.ts holds the header menu and the footer columns. A header item with a mega block opens a mega menu with link columns and an optional featured image; items without one are plain links. The mobile menu is generated from the same data.

Lookbook hotspots

Each room in data/collections.ts has a photo and a list of hotspots. x and y are percentages from the photo's top-left corner: 

{ product: "dune-modular-sofa", x: 25, y: 68 },

Set ratio to your photo's real proportions (width / height, e.g. "3 / 2") so markers stay on the right object at every screen size. To find coordinates, open the photo in any image editor, hover over the object, and divide its position by the image size.

Blog posts (MDX)

  1. Create content/blog/my-post.mdx and write it in Markdown.
  2. Add an entry with slug: "my-post", a title, excerpt, category, cover image key, author and date in data/blog.ts.

Posts can use tables and three built-in components:

<Callout title="Measure twice">Check every doorway on the way in.</Callout>
<ProductCallout slug="fjell-three-seat-sofa" />
<Figure image="room-cream" caption="Soft neutrals in a north-facing room" />

Add your own components, or change how headings, lists and quotes look, in src/mdx-components.tsx.

Other pages

Page Content file
About data/about.ts: story, numbers, values, process, team
FAQ data/faq.ts: grouped questions (also published as FAQ structured data)
Contact data/stores.ts: showrooms with OpenStreetMap maps (no API key)
Account data/account.ts: demo customer, sample orders, addresses
Coming Soon comingSoon in data/site.ts: title, text, launch date, image
Product tabs shippingInfo in data/site.ts
Privacy, Terms, Cookies, Shipping & returns data/legal.ts. {store}, {email} and {url} are filled in from data/site.ts. The cookie page has a button that reopens the cookie banner.

The policy pages are starting templates written for a typical online furniture store, not legal advice. Have them reviewed for your business and the countries you sell to before launch.

To get a map for your address: open openstreetmap.org, find the location, choose Share → HTML, and copy the iframe's src into map.

The /elements/ page shows every component and token; it's useful while rebranding. Remove it (and its menu link) before launch if you like.

Cart, promos & sets

  • Promo codes: promoCodes in data/site.ts, each with a percentage. Codes are not case-sensitive.
  • "Complete the look" sets: data/bundles.ts. When every product in a set is in the cart, the set's percentage comes off one of each, shown as its own line in the totals. Sets appear on the page of every product they include.
  • Free delivery meter: freeShippingThreshold.
  • Delivery estimate: parsed from each product's leadTime plus a transit time by ZIP zone in src/lib/delivery.ts. Replace transitDays with your carrier's rates.

In the demo, the cart, wishlist, recently viewed items, orders and requests are stored in the visitor's browser. Connect a platform (next section) for real orders.

Pop-up, cookies & analytics

Newsletter pop-up

newsletter.popup in data/site.ts: enabled, delaySeconds, daysBetween and the offer text. It waits until the cookie choice is made, never opens over another dialog, and never shows on checkout or Coming Soon. On sign-up it reveals your first promo code.

Cookie banner

analytics.cookieBanner turns it on or off. Visitors can accept all, reject optional cookies, or choose analytics and marketing separately. The cart and wishlist are strictly necessary storage and work either way.

Analytics events

The template sends standard e-commerce events in Google Analytics 4 format to window.dataLayer, which Google Tag Manager reads:

view_item · add_to_cart · remove_from_cart · add_to_wishlist · begin_checkout · purchase · search · sign_up · generate_lead

To use them, paste your Google Tag Manager snippet into the <head> in src/app/layout.tsx and add GA4 tags for these events. For any other tool, listen for the DOM event: 

window.addEventListener("nordvik:track", (e) => {
  console.log(e.detail.event, e.detail.ecommerce);
});

Events wait for consent unless you set analytics.requireConsent: false. Set analytics.debug: true to log every event in the browser console while you set things up.

Connect a backend

Every page reads products and categories through one module, src/lib/catalog.ts, and every Checkout button goes through src/lib/commerce.ts. Two settings in data/site.ts choose the source:

Setting Values
catalogSource "local": data/products.ts. "shopify": products synced from your Shopify store.
checkoutMode "demo": the built-in checkout page (no payment). "shopify": sends the cart to Shopify's hosted checkout.

Shopify, step by step

  1. Try it with Shopify's public demo store first (no account needed): 
    SHOPIFY_STOREFRONT_URL=https://furniture.mock.shop/api npm run catalog:shopify
  2. For your store: in Shopify admin, add the free Headless sales channel (or create a custom app with Storefront API access), give it read access to products and collections and write access to carts, and copy its public Storefront access token. Copy .env.example to .env.local and fill in, using a currently supported API version in the URL (Shopify supports each version for about a year): 
    SHOPIFY_STOREFRONT_URL=https://your-store.myshopify.com/api/2026-07/graphql.json
SHOPIFY_STOREFRONT_TOKEN=your-storefront-token
NEXT_PUBLIC_SHOPIFY_STOREFRONT_URL=https://your-store.myshopify.com/api/2026-07/graphql.json
NEXT_PUBLIC_SHOPIFY_STOREFRONT_TOKEN=your-storefront-token
  3. Run npm run catalog:shopify. It writes data/shopify/catalog.ts and prints your store's currency (set currency in data/site.ts to match).
  4. Set catalogSource: "shopify" and checkoutMode: "shopify", then npm run build.
  5. Re-run the sync and rebuild whenever products change. On Vercel or Netlify you can run both in the build command, and trigger a rebuild from a Shopify webhook.

The sync maps Shopify data onto the template: collections become categories; Color, Finish, Fabric and Upholstery options become color swatches; other options (Size, Material…) become selectors with price differences; stock, compare-at prices and variant IDs are kept for checkout. Storefront tokens are designed to be public: they can read products and create carts, nothing else.

Shopify has no standard dimensions or reviews fields, so synced products hide the dimensions tab and show no reviews (the demo reviews are never attached to real products). To add dimensions, store them in product metafields and extend the mapping in scripts/sync-shopify.mjs. Update data/collections.ts hotspots, data/bundles.ts and the product slugs in data/home.ts to use your own products; sections whose products don't exist hide themselves.

Other platforms

For Medusa, Saleor, BigCommerce, a headless CMS or your own API, write a script that outputs the same Product and Category shapes (documented in data/products.ts), point src/lib/catalog.ts at it, and add a branch to startCheckout in src/lib/commerce.ts that returns your checkout URL (for example a Stripe Checkout session created by your API).

Connect forms

The newsletter, contact, review, back-in-stock, swatch and account forms validate input and show a confirmation, but don't send data anywhere by default. Each one has a comment marking where to add your service: a form backend such as Formspree or Netlify Forms, your email platform's API, or your auth provider.

SEO

  • Every page has a title, description and canonical address. Product and blog pages share their own photo; other pages use public/og.png.
  • /sitemap.xml lists every page, category, product (with images) and post. /robots.txt points to it and keeps cart, checkout, account and wishlist pages out of search.
  • Structured data: Product (price, stock, rating, dimensions) and BreadcrumbList on product pages, BlogPosting on posts, FAQPage on the FAQ.
  • The shop's static HTML lists every product, so search engines see the full catalog without running JavaScript.

Set site.url before building, then submit https://your-domain/sitemap.xml in Google Search Console.

Deployment

npm run build produces a complete static site in /out. It runs a small post-build step (scripts/flatten-prefetch.mjs) that fixes a Next.js 16 static-export issue where page prefetches would return 404s on static hosts. Leave it in place.

Vercel

  1. Push the project to GitHub, GitLab or Bitbucket.
  2. Import it at vercel.com/new. Vercel detects Next.js; keep the defaults.
  3. For Shopify, add the environment variables from .env.example in Project Settings → Environment Variables.

Netlify

  1. Import the repository at app.netlify.com/start.
  2. Build command: npm run build. Publish directory: out.

Any static host

Upload the contents of /out to any web server or object storage (Cloudflare Pages, GitHub Pages, S3 with CloudFront, cPanel hosting…). Configure the host to serve 404.html for unknown addresses. URLs end in a slash (/shop/), which every host supports. To serve the site from a subfolder, set basePath in next.config.ts.

Testing & quality

The template ships with a Playwright end-to-end suite that tests the built site: shop filters and category pages, product options and price changes, delivery estimates, swatches, sets, cart totals and promo codes, checkout validation and order tracking, the header, persistence, the style switcher, consent and analytics, the pop-up, mobile drawers, and every page in light and dark mode with and without reduced motion. 

npx playwright install chromium   # once
npm run build
npm run test:e2e

Already have Chrome? Skip the install and run PW_CHANNEL=chrome npm run test:e2e.

Lighthouse

Measured on the demo build (median of three runs):

Category Desktop Mobile (slow 4G)
Performance 98–100 80–90, depending on the page
Accessibility 100 100
Best Practices 100 100
SEO 100 100

Mobile scores depend mostly on your photos: export them as WebP or AVIF at about 2000px wide and host them on your own domain or CDN. Lab scores also vary between machines and runs, so check your deployed store with PageSpeed Insights, which uses Google's consistent test hardware.

Accessibility

  • WCAG AA color contrast in every preset, light and dark.
  • Keyboard support throughout: mega menu, drawers and dialogs (focus is trapped and restored, Escape closes), tabs (arrow keys), sliders, carousels and swatches. Visible focus rings everywhere.
  • A "Skip to content" link, landmarks and a logical heading order on every page.
  • Forms label every field, announce errors and move focus to the first one.
  • Motion respects the operating system's reduced-motion setting: reveals, the hero, the marquee and the background video stop. Autoplaying content has a pause button.

When you add content, write meaningful alt text for photos and keep headings in order.

Troubleshooting

Photos don't load

The demo photos load from Unsplash, so they need an internet connection. Switch to your own photos or to placeholder mode (Images).

How do I change the currency?

Set currency and locale in data/site.ts, then update prices and the free-delivery threshold.

How do I remove the demo extras?

Set demo.styleSwitcher: false. Delete the home layouts and pages you don't need from src/app/(site)/ and remove their links in data/navigation.ts. Turn off the pop-up with newsletter.popup.enabled: false.

A page I added shows a 404 after deploying

Static exports only include pages known at build time. Rebuild after adding products, categories or posts, and make sure dynamic pages list their slugs in generateStaticParams.

The build fails after editing data

Run npm run typecheck. TypeScript names the file and field, for example a product whose category doesn't exist or a misspelled image key.
